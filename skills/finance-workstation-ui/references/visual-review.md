# Visual Review for Finance Workstations

Use this review for substantial redesigns and reference-driven work.

## Reference Extraction

Record the decisions that actually matter:

- canvas, header, panel, and inset-surface colors;
- primary, secondary, muted, positive, negative, and warning text colors;
- body, label, section-title, and display-value sizes;
- major page inset, panel gap, panel padding, and row height;
- navigation model, grid columns, and responsive collapse;
- radius, border, shadow, and focus treatment.

Do not reproduce logos, avatars, account identifiers, decorative charts, or arbitrary example content from the reference.

## Desktop Inspection

At the primary desktop viewport, check that:

- the first screen communicates system state and the main decision surface without a large dead zone;
- section starts share a clear vertical rhythm;
- panel boundaries are visible without bright outlines;
- repeated values align and use tabular numerals;
- secondary text remains readable but does not compete with primary values;
- selected navigation reads as active without resembling a glowing pill;
- actions are visually distinct from static labels.

## Narrow-Screen Inspection

On narrow screens:

- allow primary navigation to scroll horizontally or collapse deliberately;
- stack grids in decision order;
- preserve minimum readable type size;
- convert wide ledgers into labeled rows without hiding critical risk values;
- keep touch targets at least 40px high where practical;
- avoid fixed-height panels and horizontal page overflow.

## Anti-Template Check

Revisit any result that depends on several of these at once:

- identical rounded cards for every content type;
- large gradient hero areas;
- glassmorphism or neon glows;
- arbitrary icon badges;
- oversized headings paired with tiny operational text;
- excessive uppercase labels or letter spacing;
- decorative charts unsupported by real data;
- empty space introduced only to make the interface feel premium.

The interface should look specific to the user's workflow and data, even when its visual language is restrained.
